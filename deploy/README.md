# نشر نسخة تجريبية أونلاين على Render

الإعدادات دي بتجهّز **ديمو تجريبي فقط**، مش خدمة طبية أو جاهزة لاستقبال بيانات صحية حقيقية. `render.yaml` و`deploy/Dockerfile` بيشغّلوا الواجهة والـNode API على نفس الرابط، وخدمة CSM Python على `127.0.0.1` داخل الحاوية فقط. الواجهة بتوصل للـAI من خلال API الباك المحمي، مش مباشرة. مفيش نموذج CSM معتمد مرفق؛ الديمو ممكن يرجّع `INSUFFICIENT_DATA` بدون تنبؤ.

## المطلوب منك خارج المشروع

- حساب Render متوصل بالمستودع، وخطة تدعم Docker (راجع التكلفة والقيود عند الاختيار).
- قاعدة MongoDB مُدارة، مثل MongoDB Atlas، وأنشئ مستخدم قاعدة بيانات محدود الصلاحيات. اسمح لشبكة Render بالوصول حسب إمكانيات الخطة؛ لو هتستخدم وصولًا عامًا، طبّق أقل صلاحيات ممكنة واستخدم بيانات تجريبية فقط. إعداد الشبكة حسب مزوّد قاعدة البيانات وخدمة الاستضافة.
- خدمة SMTP حقيقية للتسجيل والتحقق من الإيميل. تحقّق من منافذ SMTP المدعومة في خطة الاستضافة؛ بعض الخطط تمنع المنافذ المعتادة. من غير إعداد بريد صحيح التسجيل لن يرسل رمز التحقق، ولا يتم طباعة الرمز في وضع production.

## خطوات Render

1. في Render اختر **New → Blueprint**، ووصل مستودع GitHub واختر البرانش `arena/9281a8e5-astronaut-health-monitoring-ap` (أو فرعًا مدموجًا فيه التغييرات لاحقًا). Render سيقرأ `render.yaml` من جذر المستودع.
2. أثناء الإعداد أو في Environment الخاصة بالخدمة، أضف القيم التالية **داخل لوحة Render فقط**. لا تضعها في Git أو ترسلها في المحادثة:
   - `MONGO_URI`: رابط MongoDB الكامل، بما فيه اسم قاعدة البيانات وبيانات المستخدم.
   - `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM`: من مزوّد البريد.
   - `SMTP_SECURE`: `true` للاتصال الضمني TLS إذا كانت الخدمة تتطلبه، أو `false` للاتصال الذي يستخدم STARTTLS حسب إعداد المزوّد.
   - `JWT_SECRET` يُولَّد بواسطة Render تلقائيًا وفق إعداد الـBlueprint. احتفظ به سرّيًا؛ تغييره ينهي صلاحية الجلسات.
3. أكمل إنشاء الخدمة وانتظر الـbuild والـdeploy. Render يعطي رابط HTTPS عند نجاح النشر. لو الخدمة لا تبدأ، راجع Logs بدون مشاركة الأسرار. فشل الاتصال بقاعدة البيانات يمنع الباك من بدء التشغيل.
4. افتح `<your-service-url>/api/health` وتأكد من رجوع JSON بنجاح. بعد ذلك افتح الرابط الأساسي، وأنشئ حساب اختبار، واستقبل رمز التحقق عبر البريد، ثم سجّل الدخول وجرّب تسجيل قياس تجريبي وبطاقة AI.

لو هتنشر يدويًا بدل Blueprint، اختر Docker وحدد `deploy/Dockerfile` واضبط نفس المتغيرات، و`NODE_ENV=production`. المنصة لازم تمرّر `PORT` للباك؛ الحاوية تستخدم 8000 داخليًا للـAI. لا تجعل منفذ الـAI عامًا.

## ملاحظات وحدود

- ملفات البناء والوصفة **ليست نشرًا فعليًا**. يجب إنشاء الخدمة، قاعدة البيانات، والبريد على حساباتك قبل الحصول على رابط يعمل.
- لا توجد بيانات صحية حقيقية أو أمان إنتاجي مضمون في هذا النموذج. يحتاج مراجعة أمنية شاملة، rate limiting، حماية حسابات، مراقبة، وإعدادات خصوصية وتشغيل قبل أي استخدام حقيقي.
- لا تستخدم البيانات الشخصية في الديمو. احتفظ بالنسخ الاحتياطية وإعدادات الوصول لدى مزوّد قاعدة البيانات.
- `health` يثبت أن Node يستجيب بعد الاتصال المبدئي بقاعدة البيانات، لكنه لا يضمن سلامة MongoDB أو SMTP أو AI لاحقًا. جرّب التسجيل والتفعيل والـAI أيضًا بعد النشر.
- الديمو يحتوي CSM فقط من خلال الباك؛ endpoint تحليل العلامات الحيوية المنفصل في Python غير متاح عبر الواجهة. لا توجد Ollama/RAG في صورة النشر.
- وصفة Docker وRender تحتاج اختبارًا على المنصة؛ لا يتوفر Docker أو حساب Render داخل بيئة المعاينة الحالية.
