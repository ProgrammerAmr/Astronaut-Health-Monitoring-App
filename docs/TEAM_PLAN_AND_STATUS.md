
# Team Plan and Status
## Astronaut Health Monitoring App

## 1. Team Overview

The project is developed by a six-member multidisciplinary team.

The team is divided into three main areas:

- AI / Data Science
- Backend Development
- Flutter Development

The team follows an owner-based task assignment approach. Every task must have one clearly identified owner.

| Member | Primary Role | Main Responsibilities |
|---|---|---|
| Amr | AI Lead / Team Coordinator | Coordinate AI work, support technical decisions, track integration, and coordinate overall progress |
| Mohammed | AI / LLMs | Research and experiment with suitable AI/LLM approaches and contribute to AI-related tasks |

| Nouran | Backend Developer | Implement backend APIs, application logic, and data communication |

Responsibilities may evolve as the project requirements become clearer.

## 3. Ownership Rules

- Every GitHub Issue must have one primary owner.
- The owner is responsible for implementation, testing, and reporting progress.
- Other team members may support the owner.
- Shared tasks must still have one accountable owner.
- Cross-component changes must be communicated to affected members.
- The Team Coordinator tracks progress but does not automatically own every task.

## 4. Team Coordination

The team should maintain:

- One shared GitHub repository.
- One central project board.
- Clear GitHub Issues for tasks.
- Documented technical decisions.
- Regular progress updates.
- Early integration between frontend, backend, and AI components.

GitHub is the canonical source of truth for project code, documentation, and task status.

## 5. Task Workflow

Every task should follow this workflow:

1. Proposed
2. Ready
3. In Progress
4. In Review
5. Done

A task should not be marked Done until:

- The expected result has been delivered.
- Basic testing has been completed.
- Relevant documentation has been updated when necessary.
- The owner has provided evidence of completion.

## 6. Task Definition Rules

Each GitHub Issue should include:

- Clear task title.
- Description of the expected work.
- Acceptance criteria.
- Assigned owner.
- Priority label.
- Dependencies, if any.

Tasks should be small enough to complete and review within the hackathon timeline.

## 7. Integration Responsibilities

### Flutter Team
- Coordinate with Backend on API contracts.
- Use agreed request and response structures.
- Handle loading, empty, and error states.
- Test the application using real or clearly labeled simulated responses.

### Backend Team
- Provide documented API endpoints.
- Coordinate with Flutter on response formats.
- Coordinate with AI on analysis input/output.
- Test endpoints independently.
- Provide mock responses when another component is not ready.

### AI Team
- Review available datasets.
- Document data sources and limitations.
- Perform data exploration and preprocessing.
- Select methods based on the actual problem and data.
- Provide a documented input/output contract.
- Evaluate results and avoid unsupported medical claims.

## 8. Progress Reporting

Each member should report:

- What was completed?
- What is currently in progress?
- What is blocking progress?
- What is the next expected deliverable?

Progress should be reflected in GitHub Issues and the project board.

## 9. Definition of Done

A task is considered Done when:

- Its acceptance criteria are satisfied.
- The implementation has been tested.
- The result is available in the shared repository.
- Relevant team members have reviewed integration requirements.
- The Issue has been updated and closed when appropriate.

## 10. Current Project Status

The project is currently in the planning and documentation phase.

The following documents are being established:

- PROJECT_BRIEF.md

## 11. Coordination Principle

The goal is not to keep every team member busy.

The goal is to deliver a working, integrated prototype within the available time.

Integration, testing, and demonstration are part of the project work, not activities to postpone until the end.
